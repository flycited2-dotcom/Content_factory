# grok-imagine-mcp

MCP-сервер, через который Claude Code, Codex или Claude Desktop ставят задачи генерации **видео и картинок**
в **десктоп-приложение Grok** (Imagine) по вашей подписке — без API-ключей.

## Состояние

| Часть | Статус |
|---|---|
| MCP-сервер, инструменты, валидация входа | готово, проверено тестами и реальным запуском по stdio |
| Драйвер `dry-run` (пишет задачу в `outbox`, в приложение **не** отправляет) | готов: проверяет связку «клиент → MCP → задача» |
| Разведка приложения (`recon`) | готова; **проверена только на подставных данных, на реальной Windows не запускалась** |
| Боевой драйвер, который жмёт кнопки в Grok | **не написан**: нужен отчёт разведки с вашей машины |

Пока боевого драйвера нет, каждый ответ содержит `"submitted_to_app": false`, и Claude не должен говорить,
что генерация запущена.

## Установка (Windows, PowerShell)

```powershell
cd tools\grok_imagine_mcp
python -m venv .venv
.\.venv\Scripts\pip install -e ".[uia]"
```

## Разведка приложения (один раз)

Нужна, чтобы выбрать способ управления: порт отладки (Electron/WebView2) или UI Automation.

1. Запустите приложение Grok и откройте окно Imagine.
2. `.\.venv\Scripts\python -m grok_imagine_mcp.recon` — ничего не запускает и не меняет, только читает.
3. Если в выводе «Дальше» просят перезапустить Grok с флагом `--remote-debugging-port`, сделайте это
   и запустите разведку ещё раз.
4. Откройте `recon-report.json`, **прочитайте** (там пути на диске и подписи элементов интерфейса,
   могут попасться видимые тексты) и пришлите содержимое в чат. В git файл не попадает (`.gitignore`).

## Подключение к клиентам

Путь к Python — из вашего `.venv`. Проверьте синтаксис по версии вашего клиента.

**Claude Code** (PowerShell):
```powershell
claude mcp add grok-imagine --scope user -- C:\путь\к\tools\grok_imagine_mcp\.venv\Scripts\python.exe -m grok_imagine_mcp
```

**Codex** — `~/.codex/config.toml`:
```toml
[mcp_servers.grok-imagine]
command = 'C:\путь\к\tools\grok_imagine_mcp\.venv\Scripts\python.exe'
args = ["-m", "grok_imagine_mcp"]
```

**Claude Desktop** — `claude_desktop_config.json`:
```json
{ "mcpServers": { "grok-imagine": {
    "command": "C:/путь/к/tools/grok_imagine_mcp/.venv/Scripts/python.exe",
    "args": ["-m", "grok_imagine_mcp"] } } }
```

Сервер должен работать на той же машине, где установлено приложение. Из облачной сессии Claude Code он
приложения не увидит.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `grok_generate_video(prompt, image_path?, duration_s?, aspect_ratio?)` | Видео: по тексту, а с `image_path` — из фото |
| `grok_generate_image(prompt, aspect_ratio?)` | Картинка |
| `grok_status()` | Какой драйвер активен и управляет ли он реальным приложением |

`image_path` — абсолютный путь к локальному PNG/JPG/WEBP до 20 МБ. Расширение должно совпадать с содержимым
файла, произвольные файлы в приложение не уходят. Ошибки валидации возвращаются читаемым текстом, и ничего не пишется.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GROK_DRIVER` | `dry-run` | Драйвер. Другие значения появятся после разведки |
| `GROK_OUTBOX` | `~/.grok_imagine_mcp/outbox` | Куда `dry-run` пишет задачи |

## Ограничения

- Управление интерфейсом обычной подписки может противоречить условиям сервиса xAI и упереться в лимиты подписки.
  Решение о применении — за владельцем аккаунта.
- Интерфейс приложения может измениться после обновления, тогда драйвер придётся подправить.
- Лимиты в `models.py` (длина промта, длительность, размер фото) — страховочные, а не знание о приложении.
  Их уточним после разведки.
