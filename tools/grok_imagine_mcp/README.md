# grok-imagine-mcp

MCP-сервер: Claude Code, Codex (и любой MCP-клиент) ставят задачи генерации **видео и картинок Grok Imagine**
через официальный API xAI и забирают готовые файлы на диск.

```
Claude Code / Codex  ──MCP (stdio)──▶  grok-imagine-mcp  ──xai-sdk──▶  API xAI (Grok Imagine)
   пишет промт, даёт фото                очередь задач                     ◀── видео/картинка
                                          + скачивание в папку
```

## Важно про оплату

API xAI оплачивается **отдельно** от подписки SuperGrok: по сообщениям сторонних источников, подписка не включает
API-кредиты. Ключ создаётся на [console.x.ai](https://console.x.ai), кредиты покупаются там же. Официальную документацию
xAI из среды разработки открыть не удалось, поэтому перед покупкой проверьте условия и цены на самой консоли.
Совет: завести отдельный ключ и поставить лимит трат. Фактическая стоимость генерации видео приходит в ответе
(`cost_usd`), если xAI её сообщает.

## Установка (Windows, PowerShell)

```powershell
cd tools\grok_imagine_mcp
python -m venv .venv
.\.venv\Scripts\pip install -e .
```

## Ключ

Положите ключ в файл `C:\Users\<вы>\.grok_imagine_mcp\.env` (создайте папку и файл). Так ключ лежит в одном месте
для всех клиентов и не попадает ни в конфиги клиентов, ни в git:

```
XAI_API_KEY=xai-...
```

Без ключа сервер всё равно стартует, а каждый инструмент отвечает, что надо сделать.

## Подключение к клиентам

Путь к Python — из вашего `.venv`. Синтаксис сверьте с документацией версии вашего клиента.

**Claude Code** (PowerShell):
```powershell
claude mcp add grok-imagine --scope user -- C:\путь\к\tools\grok_imagine_mcp\.venv\Scripts\python.exe -m grok_imagine_mcp
```

**Codex** — `~/.codex/config.toml`:
```toml
[mcp_servers.grok-imagine]
command = 'C:\путь\к\tools\grok_imagine_mcp\.venv\Scripts\python.exe'
args = ["-m", "grok_imagine_mcp"]
```

**Claude Desktop** — `claude_desktop_config.json`:
```json
{ "mcpServers": { "grok-imagine": {
    "command": "C:/путь/к/tools/grok_imagine_mcp/.venv/Scripts/python.exe",
    "args": ["-m", "grok_imagine_mcp"] } } }
```

Сервер работает на вашей машине и сохраняет файлы локально. Из облачной сессии Claude Code его не запустить.

## Как это работает в диалоге

Видео готовится асинхронно, поэтому схема из двух шагов:

1. Claude вызывает `grok_generate_video(prompt, …)` и получает `task_id` (статус `pending`).
2. Claude вызывает `grok_task_status(task_id, wait_s=45)`. Когда видео готово, оно скачивается в папку результатов,
   а путь приходит в `output_path`.

Картинки синхронные: `grok_generate_image` сразу сохраняет файл и возвращает путь.

Для «фото → видео» Claude передаёт `image_path` (абсолютный путь к локальному файлу) — например, к картинке,
которую он только что сгенерировал или сохранил.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `grok_generate_video(prompt, image_path?, duration_s?, aspect_ratio?, resolution?, generate_audio?, model?)` | Ставит задачу: по тексту, а с `image_path` — из фото |
| `grok_generate_image(prompt, aspect_ratio?, resolution?, model?)` | Картинка, файл сохраняется сразу |
| `grok_task_status(task_id, wait_s=0)` | Состояние задачи; готовое видео скачивается на диск |
| `grok_list_tasks(limit=10)` | Последние задачи |
| `grok_status()` | Готов ли сервер и уходят ли генерации реально в xAI |

Допустимые значения (модели, форматы кадра, разрешения) берутся из `xai-sdk` и видны клиенту прямо в схеме
инструментов. Длительность — 1–15 с. `image_path` — PNG/JPG/WEBP до 10 МБ; расширение должно совпадать
с содержимым, произвольные файлы наружу не уходят. Ссылка на готовое видео у xAI действует 24 часа, поэтому
забирайте результат вовремя.

`wait_s` ограничен 50 секундами: у некоторых клиентов таймаут вызова инструмента короткий (в Codex он настраивается
параметром `tool_timeout_sec`), поэтому не блокируем вызов надолго.

## Настройки

Переменные окружения или строки в `~/.grok_imagine_mcp/.env` (реальное окружение приоритетнее файла):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `XAI_API_KEY` | — | Ключ API xAI |
| `GROK_STATE_DIR` | `~/.grok_imagine_mcp` | Состояние: `tasks/` (по файлу на задачу) и `.env` |
| `GROK_OUTPUT_DIR` | `<GROK_STATE_DIR>/output` | Куда сохранять видео и картинки. Удобно указать папку проекта |
| `GROK_DRIVER` | `xai` | `dry-run` — только записывать задачи, ничего не отправляя и не тратя |

## Запасной путь: управление десктоп-приложением Grok

Если оплата API не подойдёт, а нужна именно подписка, в репозитории есть скрипт разведки
`python -m grok_imagine_mcp.recon` (Windows): он определяет, чем управлять приложением (порт отладки Electron/WebView2
или UI Automation). Драйвер для приложения **не написан** и тянет за собой риски: интерфейс подписки
может не поддерживаться условиями xAI, а обновление приложения ломает автоматизацию. Шаги: запустить Grok,
выполнить разведку, прочитать `recon-report.json` и прислать содержимое.
