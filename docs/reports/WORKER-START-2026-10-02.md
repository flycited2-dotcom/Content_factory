# Восстановление запуска партии 02.10.2026

Запрос владельца: шесть стиральных машин выбраны 11:00:48 МСК, в 11:05 все
показывали «ожидает», фотоагенты молчали.

## Подтверждённые причины

1. В 11:00:13 cf-excel упал до отправки задач: ConfirmStore CREATE TABLE,
   sqlite3.OperationalError: database is locked. Старые соединения commit/rollback
   не закрывали соединение и ждали блокировку только пять секунд. Конкретный
   исторический держатель блокировки не установлен.
2. В 11:10:02 первый Samsung остановил весь цикл: в кэше оставалось имя
   research_2398.png, но файла в output уже не было.
3. Таймер выполнялся раз в десять минут; подтверждение задачи не будило службу.

A1/A2 были исправны: свежие heartbeat, HTTP 204, очереди pending/processing пусты.

## Установлено на VPS

- Shared SQLite context manager: ожидание 30 секунд, обязательное закрытие.
- Ошибки submit/read/preview изолированы по товарам, сохраняют безопасный тип
  ошибки и прежний request_key. Привязка известной задачи идёт перед новым POST.
- Атомарные переходы не отменяют остановку владельца; успешная привязка снимает
  временную ошибку.
- Потерянный оригинал восстанавливается по точным brand/model из банка. Samsung
  взят из статьи 00-00000052, exact_model=true, original PNG 659822 байта.
  Архивная карточка ready_light не использовалась вместо запрошенной kbt.
- Немедленный wake после принятия /task, /make, /pick и включения мастера;
  расписание соблюдается. Сам wake не создаёт задания и не перезапускает
  выполняющийся oneshot.
- Резервный таймер каждую минуту, максимум три запуска за 60 секунд.
- /excel отделяет последнюю партию от истории, ожидание от работы A1/A2,
  показывает состояние службы и фактическую дату следующего прохода.

Бот активен, NRestarts=0. Master=on, отдельная Avito-генерация остаётся off.
Отменённые задачи и прежние 14 ошибок не запускались.

## Продолжение и материалы

- `deploy-receipt.json`: хеши установленных модулей и backup.
- `live-verification.json`: последняя партия, job IDs, файлы, состояния и отсутствие
  дублирующихся request_key.
- Backup: /opt/content-factory/state/deploy-backup-worker-start-20261002T083440Z.
- Production run.py и publish/telegram.py содержат более новые VK/proxy/media
  функции, чем локальные исходники. При внедрении применены только точечные
  изменения, функции production сохранены. Не заменять их полными старыми
  локальными версиями. Полная исходная копия: source-before.tar.gz.
- Скрипт deploy.py проверяет исходные хеши; повторный запуск после внедрения
  намеренно остановится. Новое внедрение требует новой актуальной baseline.

Партия продолжает двигаться системными службами. Повторно ставить её не нужно.
Контроль: /excel или «Контент-завод → Очередь». Отмена: кнопка
«Отменить последнюю партию». Общий аварийный останов: /generation off.
