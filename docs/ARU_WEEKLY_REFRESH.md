# АРУ: полный обход категорий по понедельникам

Актуально 10.10.2026. API нет. График: понедельник 10:00, Europe/Moscow.
Последний успешный полный прайс действует до успешной замены, без отключения через 24 часа.
Наличие относится к дате наблюдения.
`automation-3` по подтверждённому результату основной сессии сохраняет этот
график и выполняет сбор/компиляцию кандидата. **Установка на рабочий сервер
требует отдельного явного подтверждения владельца после сравнения кандидата
и резервной копии перед deploy. Снимок 10.10.2026 отдельно подтверждён владельцем и установлен; будущие замены согласуются отдельно.**

## Обязательное покрытие

`/vse-tovary/` не содержит весь ассортимент. Исторические 8 089/11 638 строк
не являются полным каталогом. Нельзя обходить только это представление,
только конечные листья или только первую страницу каждого узла.

Очередь строится из всех категорий меню, обнаруженных детей и всех
префиксов канонической категории URL каждой карточки. Включить также
`/vse-tovary/` и `/novinki/` с собственной пагинацией. Обойти **каждого
родителя с его товарами и детьми, всех детей и страницы 1..N каждого узла**.
Пустой родитель с детьми — допустимая сохранённая страница. Новые ссылки
и канонические пути добавляются в очередь до закрытия всего покрытия.
Число узлов/страниц брать из текущего сайта, не из предыдущего запуска.

## Вход и DOM

Применять computer-use и поддерживаемые CUA API выбранного браузера (Chrome или IAB). Не извлекать
cookies/токены, не переносить авторизацию на сервер. При истёкшем входе
запросить новый код владельца; коды не повторять/не сохранять. Не делать
заказов, обращений к менеджеру или платных генераций.

Создать новую `outputs/aru-refresh-YYYYMMDD-HHMM/` с `pages/` и
`categories-menu.json`, не смешивать недели. Если открыт плиточный вид,
через UI выбрать «Вид: список». DOM reader ничего не переключает сам.

Прочитать `scripts/aru_account_dom.js` разрешённым I/O внутри CUA REPL и
передать функцию в `tab.playwright.evaluate`. Читаются только данные DOM:

- Категории:`.v-catalog-menu__list a[href],.v-catalog-side__list a[href]`.
- Дети:`.v-catalog-icon__list a[href]`, заголовок:`h1`.
- Все карточки:`.v-products-list__item[data-product-id]`, без ограничения slice(0,30).
- Пагинация:`.pagination a`, фактический `?page=N`.
- Вход: ссылка «Выйти».

Возвращаются `authenticated,url,title,pages,categories,children,items`.
Оркестратор добавляет `category_id`(нормализованный URL-путь узла),`page`
(фактический номер, для первой 1) и `captured_at`(ISO8601UTC с часовым поясом).
Файлы уникальны по узлу/странице, например `elektroinstrument__002.json`.
`categories-menu.json` — массив `{id,name,url}`. ID: URL-путь с начальным и
конечным `/`, безquery/fragment; name — русская подпись меню/заголовка.

Сохранять **все карточки, включая отсутствие и под заказ**. Не фильтровать
до сверки ID: более поздний outstock должен заменить прежний instock.
Не обрезать число отрисованных карточек искусственным лимитом.

Проверять вход, фактический URL/номер/узел, текущую пагинацию. Общее число
страниц одного узла должно оставаться согласованным. Сохранять прогресс.
При сбое восстановить вкладку в том же выбранном браузере и продолжить с первой
несохранённой страницы текущего прохода. Истёкший срок или изменившуюся
пагинацию нельзя исправить подменой даты; проход собрать заново.

Проверенное восстановление 10.10.2026: в IAB авторизация сохраняется при
создании новой вкладки того же профиля. Работать короткими порциями примерно
30–40 страниц. При таймауте CDP сначала проверить состояние, затем открыть
свежую вкладку в том же выбранном браузере на URL первой несохранённой
задачи. Проверить «Выйти» и продолжить из сохранённого прогресса. Не менять
браузеры по кругу и не запрашивать OTP, если вход сохранился. Перезапуск
браузера владельцем нужен только когда создание свежей вкладки и проверки
состояния не восстановили управление.

## Компиляция без установки

Из корня Авито:

```text
python avito-bridge/scripts/refresh_aru_account.py --category-crawl --categories <новая папка>/categories-menu.json --pages-dir <новая папка>/pages --output-dir <новая папка>/compiled --compile-only
```

Компилятор:`avito_bridge.ingest.aru_categories.build_category_snapshot`;
проверка сохранённого JSON:`validate_category_coverage` того же модуля.
Требовать `completeness_basis=category_tree`, все узлы и страницы, согласованные
статистику/taxonomy. Фиксированное старое количество товаров — не проверка.

Исходные страницы свежие и укладываются в максимальный разброс 24 часа.
**Это ограничение нового прохода, не TTL действующего прайса.**
`generated_at` — самое раннее наблюдение прохода. Повторные ID сверить по
самому позднему timestamp, затем применить правила:

- Канонический сегмент `pod-zakaz` исключается независимо от текста наличия.
- Только точное «В наличии»; неизвестные/другие состояния исключаются.
- Только положительная конечная текущая персональная цена Decimal.
- Зачёркнутая цена не используется. Контент=персональная×1,10,
  округление вверх до целого рубля один раз.

`category_path` — массив русских названий;`category_ids` — стабильные ID префиксов URL.
Снимок содержит `categories[{id,name,parent_id,url,path_ids,path_names}]`
и `category_scan` с доказательством покрытия. Не заменять подписи slugами,
не обрезать пути 70 символами, не угадывать группу по названию товара.

Проверенный итог прохода 10.10:`538 / 538 (536 категорий + 2 представления)`,`1679 / 1679`,
`15142`,`11597`,
`3545: нет в наличии 3529; под заказ 15; без цены 1`,`8bd07d91ab11244a949991d13543318bb9d02641c1d99c0a876a68e97bc92076`.
Полнота и установка подтверждены: full-install-result.json; 11 597 позиций в обеих системах.

## Сравнение кандидата и подтверждение установки

После успешной компиляции показать владельцу проверяемый результат:

- Дату поставщика, SHA256, подтверждённые узлы/страницы и товары в наличии.
- Различия с рабочим прайсом: добавлено/исключено, изменения наличия/цен и
  русской иерархии. Нельзя объявлять кандидат полным до проверки покрытия.
- Пройденные локальные проверки и точный перечень файлов/данных установки.
- План резервной копии и восстановления обеих рабочих копий.

Еженедельное разрешение собирать прайс не разрешает автоматически его
устанавливать. До отдельного явного подтверждения сохраняются локальный
кандидат и отчёт, а рабочие JSON, код бота и процессы сервера не меняются.
При неизменном кандидатном результате автоматизация остаётся тихой.

После подтверждения выполнить существующую процедуру установки **именно
рассмотренного кандидата**, предварительно сохранив резервные копии:

```text
python avito-bridge/scripts/refresh_aru_account.py --category-crawl --categories <новая папка>/categories-menu.json --pages-dir <новая папка>/pages --output-dir <новая папка>/compiled --install-confirmed
```

Без `--install-confirmed` CLI только компилирует кандидат, без SSH/установки.
`--compile-only` и `--install-confirmed` взаимоисключающие. Последний флаг
фиксирует уже полученное подтверждение, сам по себе не заменяет согласие.
Еженедельный автоматический запуск не передаёт `--install-confirmed`.

SSH alias`sprintbox-itp`; кандидат в `/opt/avito-candidates/aru-refresh-*`.
Установщик резервирует оба старых JSON, проверяет кандидата и атомарно
заменяет `/opt/content-factory/state/prices/aru-catalog.json` и
`/opt/avito-bridge/runtime/aru/catalog.json`. Проверяет оба загрузчика;
при ошибке сохраняет/восстанавливает предыдущий успешный снимок.
После успеха обновляются локальные копии и `refresh-result.json`.
Неполнота, отсутствие входа, сбой браузера/SSH не очищают рабочую базу.

Процедура меняет данные, не публикационные выборы и не объявления/посты.
Новую версию кода компилятора/установщика/навигации разворачивать отдельно
согласованно с форматом, тоже после резервной копии и явного подтверждения
владельца. После изменения кода бот нужно перезапустить;
обычная будущая замена только JSON читается при обращении без restart.

## Отображение и расписание

Показывать дату поставщика и понедельничный график. При задержке данные
остаются рабочими. Telegram/Studio: русское дерево, полная пагинация,
сохраняемый выбор; bulk действует на явно выбранную область со снятием.
В Telegram `/task`: сначала поставщик из `source_names.json`, затем только
его русские разделы; категории по 10, товары по 20, своё число первых N,
номера/диапазоны и сохраняемый выбор. Подписи меняются через JSON без
перезапуска; ключи поставщика и товаров сохраняются.

Нужны включённый компьютер, работающий Codex, доступный авторизованный
браузер. При истёкшем входе нужен новый код владельца; API/автономного
серверного входа эта процедура не создаёт. Сборщик один.

При неизменных данных молчать. После значимого изменения — один краткий
отчёт о кандидате с датой/количествами и сравнением для подтверждения.
Сообщать отдельно «кандидат собран» и «рабочий прайс установлен»;
второе допустимо только после подтверждённой успешной установки.
При сбое сообщить нужное действие и сохранение
прежнего прайса. Не отправлять посты в группы, не создавать объявления,
не запускать платную генерацию.

Рекомендуемый prompt:`outputs/aru-repair-20261010/automation-prompt-category-crawl.txt`.
Основная сессия подтвердила обновление действующей `automation-3`: сбор и
компиляция в понедельник 10:00 МСК, server deploy только после отдельного
подтверждения владельца по сравнению кандидата. Автоматизацию не дублировать.
Последний успешный полный снимок продолжает работать при задержке или
отклонении нового кандидата; отсутствие подтверждения не является TTL.
