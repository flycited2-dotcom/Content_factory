# O ARK — АРУ: передача контекста для Telegram контент-агента

**Дата передачи:** 09.10.2026. **Поставщик:** АРУ, https://aru.ooo/. **Код источника:** `aru`.

Документ предназначен разработчику в другой сессии. Он описывает уже выполненную работу, готовые данные и точку подключения к агенту, который готовит и отправляет посты в Telegram-группу владельца. Повторный обход сайта и повторная проверка всего каталога для подключения агента не нужны: использовать готовый авторизованный снимок. Следующий обход нужен по расписанию для обновления цен и наличия.

## 1. Задача владельца и принятые правила

Владелец попросил добавить весь ассортимент АРУ в контент-завод и Авито. Товары для публикации выбираются позднее. Цель следующего разработчика — сделать готовый ассортимент доступным существующему Telegram контент-агенту, сохранив его действующие процессы подготовки постов, выбора, подтверждения и отправки в группу.

| Правило | Зафиксированное решение |
|---|---|
| Ассортимент | Весь каталог изучен; рабочая база содержит только подходящие товары |
| Наличие | Только явное «В наличии» на дату сбора |
| Неизвестное наличие / «Нет в наличии» | Исключать из рабочей базы |
| Цена поставщика | Текущая персональная цена из авторизованного личного кабинета |
| Цена для контента | Персональная цена +10%; округление вверх до целого рубля один раз |
| Зачёркнутая цена | Не использовать как закупочную цену |
| Скидка | Не выводить общую фиксированную скидку: персональная скидка различается между товарами |
| API АРУ | Владелец подтвердил: API нет и не будет |
| Обновление | Раз в неделю по понедельникам; настроено 10:00 МСК |
| Срок действия прайса | До следующей успешной полной замены, без отключения через 24 часа |
| Ошибка обновления | Продолжать использовать предыдущий успешный прайс |
| Выбор публикаций | Подключение базы само по себе не означает публикацию всех 8 тысяч товаров |

Наличие в снимке — булевый статус, а не количество единиц на складе и не резерв товара. Поле `stock=1` в Авито означает «есть», а не остаток одной штуки. Между недельными обновлениями фактическое наличие может измениться; в интерфейсе сохранять дату исходного прайса.

## 4. Контракт JSON

Готовый рабочий снимок — UTF-8 JSON, `schema_version=1`. Числа денежных значений передаются строками, чтобы сохранить копейки без ошибок float. Исходный товарный ID также строка.

Сведения первого рабочего снимка:

```json
{
  "schema_version": 1,
  "source": "aru",
  "complete": true,
  "authenticated": true,
  "price_basis": "account_price",
  "generated_at": "2026-10-09T16:32:14.604000+00:00",
  "pages": 346,
  "captured_pages": 346,
  "scanned_products": 10360,
  "excluded_products": 2271,
  "content_markup_pct": "10",
  "reconciled_moved_products": [{"id": "62092", "pages": [134, 308]}],
  "items": ["8089 объектов товаров; пример ниже"]
}
```

Массив `items` в блоке выше сокращён для документа; в реальном файле он содержит объекты. `generated_at` соответствует наиболее ранней сохранённой странице полного обхода, а не времени копирования файла на сервер. Это консервативная дата прайса: **09.10.2026, 19:32 МСК**. Более поздние наблюдения отдельных товаров записаны в их `captured_at`.

Пример реальной рабочей строки:

```json
{
  "id": "52069",
  "article": "150",
  "name": "150 Перчатка нейлон с ПВХ Желтая (8р) ALG 10шт. (300шт.уп.)",
  "url": "https://aru.ooo/perchatki-alg/150-perchatka-neylon-s-pvkh-zheltaya-8r-alg-10sht-300sht-up/",
  "brand": "ALG",
  "category_path": ["perchatki-alg"],
  "available": true,
  "price": "43.48",
  "price_basis": "account_price",
  "content_markup_pct": "10",
  "content_price": "47.83",
  "content_price_rub": 48,
  "captured_at": "2026-10-09T16:32:14.604000+00:00",
  "specifications": {
    "Бренд": "ALG",
    "Кратность (количество)": "10",
    "Грузоподъемность": "Стяжка  15 см."
  },
  "image_urls": ["https://aru.ooo/wa-data/public/shop/products/00/webp/69/20/52069/images/37801/37801.180.webp"],
  "description": "150 Перчатка нейлон с ПВХ Желтая (8р) ALG 10шт. (300шт.уп.)"
}
```

Характеристики переносятся из DOM как данные поставщика; пример показывает, что даже у поставщика встречаются странные или неподходящие значения. Не превращать каждое поле без проверки смысла в рекламное утверждение. `description` у многих товаров совпадает с названием. `category_path` получен из пути URL, поэтому это не готовая унифицированная классификация Telegram/Авито.

| Поле | Значение для агента |
|---|---|
| `id` | Стабильный ID товара внутри АРУ; для нового адаптера ключ `aru:<id>` |
| `article` | Артикул поставщика; не считать глобально уникальным ID |
| `name`, `brand` | Название и бренд для поиска и подписи |
| `url` | Исходная карточка товара; ссылка и возможность обогащения выбранной позиции |
| `available` | Явное наличие на время `captured_at` |
| `price` | Исходная персональная цена с копейками |
| `content_price` | Плюс 10%, округлено до копеек; поле для контроля |
| `content_price_rub` | Готовая цена для контента, целые рубли вверх |
| `specifications` | Сырые характеристики, без домысливания |
| `image_urls` | Доступные изображения из списка; обычно миниатюры 180 px |
| `generated_at` | Дата всего прайса, показываемая пользователю |

## 5. Как подключить существующий контент-завод

Предпочтительный путь в этом же проекте — использовать уже добавленный слот `aru`, а не новый парсер сайта.

Файл `src/content_factory/ingest/aru_account.py` содержит:

```python
load_account_items(prices_dir: Path, markup_pct=10)
```

Он читает `aru-catalog.json`, требует полный авторизованный снимок с базой цены `account_price`, проверяет дату с часовым поясом, не допускает дату далеко в будущем, оставляет только наличие и положительную конечную персональную цену. Возраст установленного снимка не блокирует загрузку. Возвращает список `PriceItem(section, article, brand, name, price)`, где `price` уже включает наценку и округление до целого рубля.

Файл `src/content_factory/ingest/excel_price.py` содержит общую точку подключения:

```python
from pathlib import Path
from content_factory.ingest.excel_price import load_price_slots

prices_dir = Path('/opt/content-factory/state/prices')
slots = load_price_slots(prices_dir, for_telegram=True)
aru_items = next((items for label, items in slots if label == 'aru'), [])
```

Этот код предназначен для запуска в окружении существующего контент-завода, где доступен пакет `content_factory`. **Не умножать `PriceItem.price` повторно на 1,10**: наценка применена внутри загрузчика.

`prices_dir` в действующем боте определяется как `Path(cfg.state.db).parent / 'prices'`. Если получатель работает с другим конфигом или другой state-папкой, сначала проверить фактический путь. Копия в одном репозитории не подключается автоматически к другому отдельному процессу.

### Включение источника и наценка

`state/prices/telegram_sources.json` может содержать `{"disabled": ["aru"]}`. Тогда слот виден в общей базе, но исключён из `load_price_slots(..., for_telegram=True)`. Для Telegram должен быть включён `aru`: через `/sources` или существующий `set_tg_enabled(prices_dir, 'aru', True)`. Не сбрасывать настройки других поставщиков.

`state/prices/markups.json` хранит явные переопределения наценки. Если `aru` отсутствует, действующий загрузчик использует 10%. Если есть иное значение, выяснить, не было ли оно позже задано владельцем через `/markup aru`; не применять одновременно это значение и вторую наценку в агенте. На дату этой работы правило владельца — +10%. Локально указанные файлы переопределений при проверке отсутствовали; настройки другого процесса/сервера нужно читать в его фактической state-папке.

### Важное ограничение PriceItem

Текущий `PriceItem` содержит цену, бренд, название, раздел и артикул, но **не содержит исходный `id`, URL, фотографии и полный набор характеристик**. Для текстового поиска и обычных задач этого достаточно. Если новый агент готовит богатые карточки с изображением и ссылкой, используйте сам JSON либо расширьте адаптер с сохранением `id` и остальных полей.

Не сопоставлять товар с фотографией только по похожему названию. В новом независимом адаптере надёжный ключ — `aru:<id>`. В существующем потоке контент-завода антидубль `item_key(PriceItem)` основан на `excel|бренд|модель` или названии. Это уже действующая семантика; изменение ключей требует миграции состояния, иначе возможны повторные публикации. Не считать существующий ключ автоматически равным `aru:<id>`.

## 6. Как подключить другой Telegram-агент без этого Python-пакета

Готовый JSON можно читать напрямую. Для начала использовать `data/aru-catalog.json` из архива; затем настроить доставку того же рабочего файла из `/opt/content-factory/state/prices/aru-catalog.json` в место, доступное агенту. Доступ к личному кабинету для чтения готового прайса не требуется.

Минимальная модель товара агента:

```text
supplier = aru
product_key = aru:<id>
supplier_id = id
article, name, brand, category_path
account_price = Decimal(price)
sale_price_rub = ceil(account_price * Decimal('1.10'))
available = true
supplier_updated_at = snapshot.generated_at
observed_at = item.captured_at
source_url = item.url
image_urls, specifications, description
```

Для заголовка снимка требовать `schema_version == 1`, `source == 'aru'`, `complete is True`, `authenticated is True`, `price_basis == 'account_price'`. Строки — уникальные `id`, `available is True`, `price_basis == 'account_price'`, конечная положительная Decimal-цена. Не устанавливать ограничение на возраст в 24 часа и не подменять дату поставщика текущим временем загрузки файла.

Цена с целыми рублями вычисляется так:

```python
from decimal import Decimal, ROUND_CEILING

account_price = Decimal(row['price'])
sale_price_rub = int(
    (account_price * Decimal('1.10')).quantize(Decimal('1'), rounding=ROUND_CEILING)
)
```

Например, `43.48 × 1.10 = 47.828`, итог **48 ₽**. Нельзя сначала округлить закупку до 44 ₽ и затем начислить наценку: получится другая цена. `content_price="47.83"` — контрольное значение с копейками; стандартная целая цена контента — `content_price_rub=48`.

При неудачном чтении/обновлении сохранить последнюю корректно загруженную базу. Для синхронизации файла применять атомарную замену или уже готовую процедуру, чтобы агент не прочёл недописанный JSON. Кэшировать допустимо по изменению файла/хешу; не хранить старую базу в памяти бесконечно после успешной замены.

## 7. Подключение к Telegram-группе: что проверить получателю

Конкретный отдельный агент, адрес группы и тема обсуждения не были установлены в этой работе. Существующие секреты и реальные идентификаторы не публикуются в документе. Получатель должен использовать конфигурацию того агента, которого владелец имеет в виду, и действующую группу; не создавать нового бота автоматически.

В существующем контент-заводе применяются настройки:

| Настройка | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен действующего бота из секретного окружения |
| `TELEGRAM_OWNER_CHAT_ID` | Управляющий чат владельца |
| `TELEGRAM_CHANNEL_ID` | Целевая группа/канал публикации; у раннеров есть fallback `telegram.channel_id` |
| `TELEGRAM_REVIEW_CHANNEL_ID` | Чат/канал предварительного просмотра; fallback из YAML |
| `telegram.test_channel_id` | Тестовый получатель из конфигурации, если используется существующим потоком |
| `telegram.parse_mode` | Обычно HTML |
| `telegram.min_seconds_between_posts` | Интервал между постами, по умолчанию 180 секунд |

Токены и прочие значения должны оставаться в существующей `.env`/секретном окружении, а не в этом документе, JSON-каталоге или коммитах.

Текущий `publish_post` в `publish/telegram.py` отправляет фото с подписью, использует `PublishState` для идемпотентности и обрабатывает сетевые сбои. В просмотренной реализации `_send_once` нет параметра `message_thread_id`. **Если целевая группа использует темы, маршрутизацию в нужную тему нужно реализовать/подключить в агенте отдельно.** Без темы обычный `chat_id` направляет сообщение в группу согласно Telegram-маршрутизации. Конкретные настройки группы ещё не проверены этой работой.

Для запуска подключения достаточно:

1. Определить действующий процесс агента, его репозиторий, state-папку и получателя постов.
2. Подключить слот `aru` через существующий загрузчик либо добавить адаптер готового JSON.
3. Сохранить единую наценку +10%, дату поставщика и фильтр наличия.
4. Передать названия/характеристики в существующий генератор текстов; изображения — в действующий путь подготовки карточек.
5. Подготовить один пост из выбранного товара и проверить данные/цену в существующем режиме предпросмотра.
6. Для отправки использовать текущий процесс подтверждения владельца и его настроенную группу. Добавление базы не разрешает автоматическую массовую публикацию всех товаров.

Генерация медиа не выполнялась в этом этапе. Если дальнейшая задача требует видео, анимации изображения или аватарной озвучки, пользовательские AGENTS требуют глобальный `grok-media` по инструкции `C:/Users/TLT-1/.codex/mcp/grok-media/README.md`. Техническое подключение каталога не требует платных генераций.

## 10. Будущие недельные обновления

Подробная процедура находится в `avito-bridge/docs/ARU_WEEKLY_REFRESH.md`; копия есть в архиве. Рабочий путь:

```text
Авторизованный Chrome → страницы DOM → новый полный JSON
→ проверка → SSH → резервная копия и атомарная замена в двух системах
→ проверка двух загрузчиков → локальные копии → отчёт
```

Файлы относительно avito-bridge:

| Файл | Назначение |
|---|---|
| `scripts/aru_account_dom.js` | Чистая функция чтения отрисованных карточек через CUA; без fetch и cookies |
| `scripts/refresh_aru_account.py` | Локальная компиляция, доставка кандидата, вызов серверного установщика, обновление локальных копий |
| `scripts/install_aru_snapshot.py` | Серверная проверка, резервирование, замена и откат обеих рабочих копий |
| `docs/ARU_ACCOUNT_PRICES.md` | Персональные цены, загрузчики, правила |
| `docs/ARU_WEEKLY_REFRESH.md` | Полный регламент обновления и восстановления |

Каждый новый обход хранить в новой папке `outputs/aru-refresh-YYYYMMDD-HHMM/pages`, не смешивать разные недели. На каждой странице записывать фактический номер, URL, число страниц, `authenticated`, `captured_at`. Число страниц 346 относится к первому обходу и может измениться; будущий сбор должен брать реальное число из текущей пагинации. Chrome во время первого сбора несколько раз зависал: сохранение страниц позволяло продолжить с первой несохранённой.

После полного обхода запускать из корня проекта Авито:

```text
python avito-bridge/scripts/refresh_aru_account.py --pages-dir <новая папка>/pages --output-dir <новая папка>
```

Скрипт использует пакет из соседнего репозитория `content-factory`. При переносе на другую машину нужно сохранить структуру проектов либо адаптировать путь к пакету. Серверный установщик уже развернут на указанном сервере, его также надо установить при переносе на новый сервер.

**Разница между двумя проверками возраста:**

- Для нового кандидата исходные страницы должны быть собраны в последние 24 часа: это защита от смешанного, растянутого или старого нового обхода.
- Уже установленный полный прайс не истекает через 24 часа и продолжает действовать сколько нужно до успешной замены.

Установщик проверяет схему, авторизацию, полноту, количество страниц, уникальность ID, наличие и положительные цены; сохраняет обе старые копии; проверяет оба загрузчика после замены и восстанавливает старые данные при ошибке. Его `refresh-result.json` содержит дату, число подходящих/исключённых товаров, добавления, удаления, изменения цен, путь резервной копии и `published: 0`.

## 12. Приёмка именно подключения агента

Достаточно проверять новую связь агента с готовым источником, а не повторять полный аудит сайта:

1. JSON читается, заголовок корректен; для приложенного снимка доступны 8 089 строк, без дублирования ID.
2. В общем каталоге агента виден источник АРУ со всем рабочим ассортиментом; поиск находит конкретный товар и возвращает исходный ID/артикул.
3. На примере `id=52069` закупка 43,48 ₽ приводит к конечной цене 48 ₽; второй наценки нет.
4. Дата прайса остаётся 09.10.2026 19:32 МСК для приложенного снимка, не меняется от чтения файла.
5. Строки отсутствующих и неоценённых товаров не попадают в рабочую выборку; возраст прайса не отключает каталог.
6. Фото и характеристики относятся к выбранному товару, цена упаковки не пересчитана без основания.
7. Пост проходит текущую цепочку подготовки/подтверждения; получатель и тема группы определены настройками нужного агента.
8. Повтор обработки не создаёт дубликат публикации; при обновлении файла агент видит новые данные.
9. Сбой обновления не очищает базу. Подключение Telegram не включает публикацию Авито.
