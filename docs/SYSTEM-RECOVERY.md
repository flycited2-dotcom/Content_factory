# Avito: архив и восстановление после сбоев

Актуально на 01.10.2026. Рабочие комплекты находятся на VPS в
`/opt/avito-ready-price/content/<артикул>/`: `card.png`, `original.png`,
`content.json`. В JSON сохраняются артикул, название, точная модель,
характеристики с источником, проверка текста и актуальная цена.

Общий банк карточек:
https://drive.google.com/drive/folders/1gZd706vgHtUZnTDCWk5s5yvu5ZtBerOT

Drive получает копии каждые 15 минут. Имена содержат артикул и название;
метаданные содержат SHA-256. Повторная синхронизация не загружает одинаковые
файлы. Старые резервные копии остаются в Drive, даже если их локальные
исходники больше не проходят проверку изображения. `articles` в отчёте —
число архивных артикулов на Drive; `mirrored_articles` — число комплектов,
прошедших текущую проверку для синхронизации.

## Что восстанавливается автоматически

- При обрыве сети фотоагент повторно открывает SSH-туннель. Фиксированная
  привязка к прежнему локальному IP убрана.
- Сразу после получения результата агент сохраняет отдельный журнал для
  своей дорожки в `logs/upload_outbox/<lane>/<job_id>.json`. Фото и результат
  поиска УТП досылаются до получения следующей задачи. Журнал переживает
  перезапуск процесса и Windows; готовый файл удаляется после подтверждения VPS.
- Повторная доставка выполненной задачи возвращает первое принятое имя
  файла. Потерянное подтверждение не создаёт второй результат.
- Поздний результат или ошибка отменённой задачи не возвращают её в работу.
  Локальный результат отменённой задачи остаётся для проверки, а журнал
  перемещается в `logs/upload_outbox/<lane>/cancelled/`.
- При `/avito restart` уже выполненные задания отменённой партии используются
  с сохранённого этапа: готовую карточку забирает проверка, готовый research
  переходит к карточке. Законченный этап повторно не генерируется.
- Планировщик Windows запускает `RitualB2B_Watchdog` после входа пользователя;
  watchdog поднимает Chrome и агента отдельно для A1/A2. Сохранённая ручная
  остановка дорожки учитывается. Пока ПК выключен, задачи ожидают его запуска.
- VPS-службы и таймеры включены в автозапуск. Очереди и выбранная партия
  сохраняются в SQLite. Задача прерванного агента возвращается своей группе
  аккаунта после истечения аренды; по умолчанию аренда составляет 45 минут.
- Перед новой генерацией выбранной партии конвейер проверяет Drive.
  Утраченный или неполный локальный комплект восстанавливается только для
  совпадающих артикула, бренда, модели, названия и режима карточки.
  Проверяются SHA-256 всех файлов, изображения и сохранённые доказательства.
  Старый неполный каталог сохраняется в скрытую резервную папку.
- Готовый проверенный комплект переиспользуется, а цена берётся из свежего
  прайса. При недоступном Drive либо неполном/повреждённом комплекте новые
  задачи откладываются до следующего прохода, без повторной генерации.

Сбой до получения и сохранения результата в браузере отличается от сбоя
доставки: в первом случае незавершённая задача может потребовать повторного
выполнения; во втором уже сохранённый результат досылается из журнала.

## Что видно владельцу

В Telegram-боте «Никита»:

- `/avito categories` — выбор товарной группы.
- `/avito start 5 телевизоры` — ограниченная партия; вместо телевизоров
  можно указать другую категорию.
- `/avito pause` — приостановить новые этапы; уже взятая агентом задача может завершиться.
- `/avito resume` — продолжить её.
- `/avito cancel` — отменить текущую партию.
- `/avito restart` — перезапустить генерацию по предусмотренным правилам партии.
- `/avito report` — постатейные этапы, причины задержки публикации, ссылка на
  банк и состояние восстановления.

Готовая карточка ещё должна пройти проверку товара и получить подтверждение
Avito. Генерация, добавление в XML и активация объявления — разные этапы,
они отражаются в отчёте. Старые маленькие исходники и неподтверждённые модели
сохраняются как резервные данные, но не обходят проверки публикации.

## Служебные файлы

- `/opt/content-factory/state/avito-drive-sync.json` — последняя успешная
  выгрузка; закреплённый ID папки.
- `/opt/content-factory/state/avito-drive-restore.json` — последняя проверка
  восстановления, отложенные артикулы и причины.
- `cf-excel.timer` — проход конвейера каждую минуту; принятие немедленной задачи дополнительно запрашивает запуск.
- `avito-drive-archive.timer` — копирование банка каждые 15 минут.
- `avito-ready-price.timer` — обновление фида и проверка публикации.
- `ritualb2b-api.service` — приём результатов фотоагентов.

Приватный OAuth-файл находится вне репозитория на VPS с правами 600.
Восстановление не создаёт новую папку: при недоступном закреплённом архиве
работа откладывается. Резервные копии перед внедрением находятся в
`/opt/content-factory/state/deploy-backup-20261001-restore/` и
`/root/ritualb2b/vps_api.py.backup-20261001-outbox-final`.

Остаток недельного лимита Codex не используется как условие остановки этой
работы. Реальные ограничения ChatGPT на загрузки/частоту запросов учитываются
агентом, чтобы не создавать повторяющиеся запросы при отказе сервиса.

С 01.10.2026 cf-price-sync.timer связывает принятый готовый БытТехОпт с отдельным
прайсом Контент-завода каждые 10 минут. Публикация и генерация для этого не нужны.
При устаревшем/непроверенном выпуске сохраняется последний хороший файл, а
price-sync-status.json получает deferred; /sources показывает предупреждение.
Старые копии исключаются по price_links.json только при точном SHA и пригодном
непустом преемнике. При повреждении преемника старый файл остаётся доступен.
Состояние и происхождение актуального прайса: state/prices/source_refresh.json.
Все источники со скриншота проверены: docs/reports/PRICE-REPAIR-2026-10-01.md.

С 02.10.2026 хранилища подтверждений, визарда, публикаций, ссылок и мастера
закрывают SQLite-соединения после каждой операции и ждут освобождения БД до
30 секунд. Ошибка одного товара не прерывает остальные позиции партии.
Потерянный research-исходник ищется в локальном банке по точным бренду и модели;
режим карточки не ограничивает повторное использование оригинала.
В `/excel` видны результат последнего запуска обработчика, время следующего
прохода, ожидание дорожки и фактическая работа A1/A2. Повтор запроса после
разрыва сети использует сохранённый request_key; известный результат сначала
привязывается к товару. Отмена сохраняется при позднем ответе агента.
Результат внедрения: `docs/reports/WORKER-START-2026-10-02.md`.
